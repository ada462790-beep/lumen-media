# Sicherheit

*[English below](#security-policy)*

## Eine Sicherheitslücke melden

**Bitte nicht als öffentliches Issue, Diskussion oder Pull-Request.** Eine
öffentlich beschriebene Lücke trifft jeden Lumen-Server, bevor es eine
behobene Fassung gibt.

Stattdessen vertraulich über GitHub melden:
**[Report a vulnerability](https://github.com/ada462790-beep/lumen-media/security/advisories/new)**
(Reiter *Security* im Repository › *Report a vulnerability*). Die Meldung
sehen nur die Betreuer des Projekts.

Hilfreich sind:

- welche Fassung betroffen ist (Einstellungen › Über Lumen) und wie Lumen
  läuft (Docker, Paket, App),
- was ein Angreifer tun kann und welche Voraussetzungen er braucht
  (im Heimnetz, von unterwegs, mit oder ohne Konto),
- die Schritte, um es nachzuvollziehen — ohne echte Adressen, Namen oder
  Zugangsdaten.

Wir bestätigen die Meldung so bald wie möglich, besprechen sie im
vertraulichen Advisory mit dir und veröffentlichen eine behobene Fassung,
bevor Einzelheiten öffentlich werden. Wenn du möchtest, nennen wir dich im
Advisory.

## Was dazugehört

Besonders wichtig sind Lücken, die das Datenschutz-Versprechen brechen
(die Verwaltung oder Dritte erfahren, wer was schaut), die Anmeldung oder
Verwaltungssperre umgehen, über den Vermittler Inhalte lesbar machen, die
Unterschrift der Updates aushebeln oder Dateien ausserhalb der
freigegebenen Ordner erreichbar machen.

Unterstützt wird jeweils die neueste Veröffentlichung; Korrekturen gibt es
als neue Fassung, nicht für ältere.

# Security policy

## Reporting a vulnerability

**Please do not open a public issue, discussion or pull request.** Report
privately through GitHub instead:
**[Report a vulnerability](https://github.com/ada462790-beep/lumen-media/security/advisories/new)**
(*Security* tab › *Report a vulnerability*). Only the project maintainers
can see it.

Please include the affected version, how Lumen is run, what an attacker can
do and under which conditions, and steps to reproduce — without real
addresses, names or credentials. We will acknowledge your report as soon as
possible, work with you in the private advisory and publish a fixed version
before details become public. Only the latest release receives fixes.
